# STM32 手套固件 — 蓝牙版

硬件：STM32 + 16×BNO055 IMU + 16×16 压力矩阵 → CH9438 → USB CDC / 蓝牙 SPP。

当前版本：**v2.0.6**（左手 2.0.61，右手 2.0.62）

## 变更

**2.0.6**

- 新增 `0x05` 磁力计标定帧：`valid_mask` 2B + 16 路 `CALIB_STAT` = 18B，0.5Hz，有线无线都发。
  标定等级搭在四元数读命令里顺带取回（一次读 `0x20~0x35`），磁力计不额外占 UART 通道。
  **这 16 字节是物理 IMU 0~15 的顺序，不做手型重排**（`0x02` 是关节序，下标含义不同）；
  判磁力计只看 `CALIB_STAT & 0x03`（`bit[1:0]`=MAG、`[3:2]`=ACC、`[5:4]`=GYR、`[7:6]`=SYS，3 = 已标定）。
  只看姿态和压力的上位机忽略这一帧即可；接口说明见 `数据采集手套_数据接口说明_v2.0.6`。
- `seq` 不再借用 bit15：恢复为完整 16 位序号，磁力计状态改由 `0x05` 帧表达（`mag_ready` 模块删除）。
- 修"上电就挂死、该路一帧都没有"：帧路径里那个会无界等待的 `flush_rx` 删掉了（它一次能把同帧其余
  15 路一起拖到超时）；CH9438 读写寄存器加 3us 间隔、FIFO 改计数读；开机漏扫/挂死的通道先隔离、
  再补两轮，运行中还会自动复活，不用断电重上电。
- 修矩阵帧率偏低（实测 51.7fps）：一行的 4 次 DMA 改成在中断回调里链式推进，主循环只管 16 行和
  超时中止。现在稳定 **60.0fps**。
- USB 发送队列 2 槽 -> 3 槽；蓝牙链路补齐磁力计帧（两条链路发出的字节仍然完全一样）。

**2.0.5**

- 整理项目文件：固件源码按功能域分层（`Board` / `Imu` / `Matrix` / `Usb` / `Bt` / `System`），
  `main.c`、`boot_main.c` 只留主函数与中断；删掉重复定义的 `Error_Handler`、死头文件和过时说明。
- 消除隐患：量产脚本写 dongle 时改为 `AT+LINKCFG=0`（原先是 1 —— 那是"扫到谁连谁"，
  工位上两台 dongle 会互相配对，之后一直维持这段错误配对，表现是两边都"已连接"却一个字节都没有）。
- 消除隐患：压力矩阵上位机打包成 exe 后，行列映射配置与录制 CSV 改到 exe 旁边
  （原来写进临时解包目录，退出即丢）。
- 功能与协议未变：01/02/03/04 帧格式、状态帧 4 行内容都与 2.0.4 一致。

**2.0.4**

- 01 状态帧改成固定 4 行：`BT MAC=` / `9438=` / `055=` / `OK`。版本号那行去掉了，帧头本来就有；
  坏掉的传感器也不再逐路列，看 `055` 掩码的 0 位（开机就没起来的）和每帧 02 的 `valid_mask`（当前哪些有效）。
- 有线、无线改成同一份建帧代码，两条链路出去的字节完全一样。
- 修了蓝牙上行会哑掉的问题：USART1 出错后 HAL 会把接收关掉且不再重挂，表现是数据一切正常、
  但 ping 没应答、给 dongle 发 AT 也没反应。现在 UART 错误回调和主循环看门狗都会自动重挂。
  遇到旧固件这个现象，复位手套就好，不是 dongle 的事。
- 上位机（imu_monitor / matrix_gui）串口读取粒度改了，无线 ping 显示的延迟不再虚高。

**2.0.3**

- 跟主线 v1.2.11 同步：ping 往返延迟测量、中断服务函数重构、磁力计就绪检测模块化。
- 修量产读不到 MAC：未绑定时如果模块已经连着（产线 dongle 就在旁边），旧固件会跳过读 MAC、
  写模块配置那一步，01 帧上报空 MAC。
- ping 有线和无线都能测，应答都是 `04` 帧，上位机一套解析。
- 01 帧加了 CH9438 / BNO055 在线掩码。

## 文件

只有 bin，没有 hex。

| 文件 | 烧录地址 | 说明 |
|---|---|---|
| `bootloader.bin` | `0x08000000` | 出厂烧一次，左右手共用 |
| `left/stm32_imu_usb.bin` | `0x08008000` | 左手 |
| `right/stm32_imu_usb.bin` | `0x08008000` | 右手 |

版本和左右手读帧头第 3~5 字节：左手 `02 00 61`，右手 `02 00 62`（末位 = patch×10 + 手型码）。
2.0.4 之后的 01 帧里已经没有版本文字了，别再去文本里找。

## 烧录

1. 先烧 `bootloader.bin`（`0x08000000`），出厂烧过的跳过
2. 再烧对应手的 APP（`0x08008000`），也可以用 USB OTA

## 换机

拔插一次 dongle 就行，手套重启会自动连。dongle 的自动重连不太靠得住，没连上就在它待机
（`SPPSTAT=1`）时补发一次 `AT+SPPCONN=<手套MAC>`。

另外：一个工位同一时刻**只插一只 dongle**；备用的那只把 `AT+LINKCFG=0`、`AT+AUTOCONN` 保持默认即可，
两台同时插着又都开着自动搜索会互相配对。

## 实测（Windows + BP101Y，2.0.6）

- 无线双手同测（两个 COM 口、两只 dongle）：0x02 / 0x03 都稳在 60.0 fps，25 秒窗口内全局丢帧
  0.00%；固件侧帧间隔中位 16.7 ms（手套这边的节拍是准的），ping 往返 35~72 ms。
- 矩阵 256 路无恒零、无饱和；IMU 16 路有效位齐全，四元数模长 1.0000。
- 偶发的多秒停顿（见过一次 1.67 s、丢 256 帧）只出现在一条链路上，另一只手同一时刻一帧不丢，
  且停顿期间固件时间戳仍然规整 —— 判断在 dongle / USB / 主机这一段，不是手套采集。

## 实测（Windows + BP101Y，2.0.5）

- 有线：双流稳在额定帧率（0x02 / 0x03 各约 60 fps，合计约 32 KB/s），CRC 错帧 ≤0.01%，
  四元数模长全部 1.0000，256 路压力无死通道、无触顶。
- 无线：双流同样稳在额定帧率，ping 应答 30/30，往返延迟中位约 36 ms（最小 27 ms / 最大 48 ms，
  有数据流时测得）。偶发的整帧丢失发生在模块/RF 那一段，主机侧收到的帧率不受影响。
- 有线往返延迟约 0.1~0.2 ms（空闲时测）。工具上显示的值还会加上它自己的串口读取粒度。
